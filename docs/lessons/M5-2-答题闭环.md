# M5-2：答题闭环 —— 让面试真的能进行下去

> **前置**：M5-1 已完成（出题能落库，`POST /{id}/generate` 返回 10 道题）。
>
> **本步目标**：补齐三个能力，让一场面试能从头走到尾：
>
> 1. 看"现在该答哪一题"
> 2. 提交回答，自动推进到下一题
> 3. 答完最后一题，自动结束
>
> 做完之后，你可以用 curl 一条一条答完 10 道题，不需要任何 AI 参与。

---

# 第 0 部分：这一步在做什么

## 0.1 现在的状态

```
已有：10 道题躺在 interview_questions 表里
缺：  没有"答题"这个动作
```

数据库里那一列 `current_question_index` 一直是 **0**，因为从来没有人推进过它。

## 0.2 加进来之后

```
用户：我现在该答哪一题？
系统：查会话的 current_question_index = 0 → 返回第 0 题

用户：我的回答是"HashMap 扩容时……"
系统：① 把回答存到第 0 题
      ② current_question_index 改成 1
      ③ 给第 1 题打上"已问"时间
      ④ 返回第 1 题

…… 重复 10 次 ……

用户答完第 9 题
系统：① 存回答
      ② current_question_index 改成 10
      ③ 状态改成 COMPLETED，记下结束时间
      ④ 返回"已结束"
```

## 0.3 一个指针，两个状态

整个进度只用两个东西表示：

| 东西 | 在哪 | 含义 |
|---|---|---|
| `current_question_index` | `interview_sessions` 表 | **指针**：现在该答第几题（从 0 开始） |
| `status` | 同上 | **状态**：进行中 / 已结束 |

几条不变式（任何时刻都必须成立）：

```
IN_PROGRESS  ⟺  current_question_index <  total_questions
COMPLETED    ⟺  current_question_index == total_questions
```

**注意 `current_question_index` 指的是"下一道待答题"，不是"已答了几道"。**

答完第 0 题后它变成 1 —— 意思是"第 0 题答完了，现在该答第 1 题"。因为题目下标从 0 开始，所以 `current_question_index` 的值**恰好等于已答的题数**。这个巧合很方便。

# 第 1 部分：数据库加两列

## 1.1 新建 `src/main/resources/db/migration/V5__add_interview_answer.sql`

```sql
-- V5: 面试题目的回答
ALTER TABLE interview_questions ADD COLUMN answer_text TEXT;
ALTER TABLE interview_questions ADD COLUMN answered_at TIMESTAMP(6);
```

## 1.2 为什么是"加两列"而不是"新建一张表"

判断标准：**一问一答，还是多问多答？**

```
现在：一道题 只能 答一次       → 一对一 → 加两列
将来：一道题 允许 反复作答     → 一对多 → 才需要新建答案表
```

现在是一对一，加列最省事：不用写 join、不用建新仓库、不用管外键。

**什么时候必须改**：如果将来做"重答/多次尝试"，就得把回答拆到独立表。到那时再改，现在不用提前设计。

> 这是"**不要为想象中的需求做设计**"的实际应用。

## 1.3 两个新列的用途

| 列 | 类型 | 什么时候写 | 什么时候读 |
|---|---|---|---|
| `answer_text` | `TEXT` | 用户提交回答时 | 看结果、将来 AI 评分 |
| `answered_at` | `TIMESTAMP` | 用户提交回答时 | 判断"这题答过没有"（幂等）、算答题耗时 |

**为什么需要 `answered_at` 而不能只看 `answer_text` 是否为 null**：

因为"用户提交了一个空回答"和"用户还没答"是两件事。有独立的时间戳，就能区分：

```
answer_text = NULL,    answered_at = NULL      → 还没答
answer_text = '',      answered_at = 有值      → 答了，但内容是空
```

    @Column(name = "answer_text", columnDefinition = "TEXT")

# 第 3 部分：三个 DTO

## 3.1 `AnswerRequest`（新增）

`src/main/java/com/interviewmind/modules/interview/model/AnswerRequest.java`

```java
package com.interviewmind.modules.interview.model;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

/** 提交回答的请求体 */
public record AnswerRequest(

        @NotBlank(message = "回答内容不能为空")
        @Size(max = 5000, message = "回答过长，最多 5000 字")
        String answerText) {
}
```

**为什么要有 `@Size`**：`answer_text` 列是 `TEXT`（理论上可以非常大），但一个面试回答超过 5000 字基本是粘贴了整篇文章。限制一下能防止：
- 用户误粘贴一大段
- 将来喂给 AI 评分时超出上下文

**为什么 `@NotBlank` 而不是 `@NotNull`**：`@NotNull` 只拦 `null`，拦不住空字符串 `""` 和全是空格 `"   "`。`@NotBlank` 三个都拦。

## 3.2 `CurrentQuestionResponse`（新增）

`src/main/java/com/interviewmind/modules/interview/model/CurrentQuestionResponse.java`

```java
package com.interviewmind.modules.interview.model;

import com.interviewmind.modules.interview.model.response.QuestionResponse;

/**
 * "现在该答哪一题"的返回结构。
 * 面试结束后 question 为 null —— 前端靠这个判断"没有下一题了"。
 */
public record CurrentQuestionResponse(
        Long sessionId,
        String status,
        int currentIndex,
        int totalQuestions,
        QuestionResponse question) {
}
```

**为什么把 `status` 和 `question` 都返回**：

前端只发一个请求，就要能回答三个问题：

1. 面试结束了吗？（看 `status`）
2. 现在第几题 / 一共几题？（看 `currentIndex` / `totalQuestions`，用来画进度条）
3. 题目内容是什么？（看 `question`）

如果只返回题目，前端就没法知道"这是不是最后一题"。

**`question` 为 null 是一个信号**，不是错误。这和 M3 里"简历还没分析完时返回 `overallScore: null`"是同一个思路：**轮询/查询类接口要用数据表达状态，而不是用报错表达状态。**

## 3.3 `SessionResultResponse`（新增）

`src/main/java/com/interviewmind/modules/interview/model/SessionResultResponse.java`

import java.util.List;

/** 一场面试的完整问答记录（不做评分，只回放） */

        String skillId,
        String status,

        int answeredCount,

**注意它仍然不含 `expectedPoints`**。参考答案要点到今天为止仍然只存在于数据库里，一次都没有出去过。将来做评分时，它也只会在"评分结果"里出现，而不是在"题目"里。

# 第 4 部分：仓库加一个查询

## 4.1 `InterviewQuestionRepository` 追加

```java
    /** 按"哪场面试 + 第几题"精确查一道题 */
    Optional<InterviewQuestionEntity> findFirstBySessionIdAndQuestionIndex(Long sessionId, int questionIndex);
```

需要补 import：

```java
import java.util.Optional;
```

**为什么用 `findFirstBy` 而不是 `findBy`**：

`findBySessionIdAndQuestionIndex` 在数据库层面可能返回多行（虽然我们的唯一约束保证只有一行）。用 `findFirstBy` 让 Spring Data 生成 `LIMIT 1`，返回值类型就是 `Optional<T>` 而不是 `List<T>` —— 语义更准确，也不会因为"理论上的多行"抛 `IncorrectResultSizeDataAccessException`。

**这是一个防御性选择**：即使将来唯一约束被误删，这个查询也不会炸。

# 第 5 部分：答题服务

## 5.1 新建 `src/main/java/com/interviewmind/modules/interview/service/InterviewAnswerService.java`

```java
package com.interviewmind.modules.interview.service;

import com.interviewmind.common.exception.BusinessException;
import com.interviewmind.common.exception.ErrorCode;
import com.interviewmind.modules.interview.model.backendModel.CategoryQuota;
import com.interviewmind.modules.interview.model.response.CurrentQuestionResponse;
import com.interviewmind.modules.interview.model.entity.InterviewQuestionEntity;
import com.interviewmind.modules.interview.model.entity.InterviewSessionEntity;
import com.interviewmind.modules.interview.model.response.QuestionResponse;
import com.interviewmind.modules.interview.model.status.InterviewSessionStatus;
import com.interviewmind.modules.interview.model.SessionResultResponse;
import com.interviewmind.modules.interview.repository.InterviewQuestionRepository;
import com.interviewmind.modules.interview.repository.InterviewSessionRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import tools.jackson.core.JacksonException;
import tools.jackson.core.type.TypeReference;
import tools.jackson.databind.ObjectMapper;

import java.time.LocalDateTime;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

@Slf4j
@Service
@RequiredArgsConstructor
public class InterviewAnswerService {

    private final InterviewSessionRepository sessionRepo;
    private final InterviewQuestionRepository questionRepo;
    private final ObjectMapper objectMapper;

    /** 看"现在该答哪一题"。面试已结束时不报错，返回 status=COMPLETED + question=null */
    @Transactional(readOnly = true)
    public CurrentQuestionResponse current(Long sessionId) {
        InterviewSessionEntity session = loadSession(sessionId);
        return currentOf(session, parsePlan(session.getPlanJson()));
    }

    /**
     * 提交当前这一题的回答，返回下一题（或"已结束"）。
     *
     * 这里可以放心用 @Transactional：
     *   整个方法里没有任何网络调用（不像出题要等 AI 30 秒），
     *   只是两次数据库写，毫秒级完成，不会长期占着连接。
     */
    @Transactional
    public CurrentQuestionResponse answer(Long sessionId, String answerText) {
        InterviewSessionEntity session = loadSession(sessionId);

        if (session.getStatus() != InterviewSessionStatus.IN_PROGRESS) {
            throw new BusinessException(ErrorCode.INTERVIEW_SESSION_STATE_INVALID,
                    "面试已结束，无法继续作答");
        }

        List<CategoryQuota> plan = parsePlan(session.getPlanJson());
        int index = session.getCurrentQuestionIndex();

        // 兜底：进度已经到底但状态没改（正常流程不该出现，防脏数据）
        if (index >= session.getTotalQuestions()) {
            log.warn("进度越界，直接结束会话: sessionId={}, index={}", sessionId, index);
            finish(session);
            sessionRepo.save(session);
            return currentOf(session, plan);
        }

        InterviewQuestionEntity question = questionRepo
                .findFirstBySessionIdAndQuestionIndex(sessionId, index)
                .orElseThrow(() -> new BusinessException(ErrorCode.INTERVIEW_QUESTION_NOT_FOUND,
                        "第 " + (index + 1) + " 题不存在，sessionId=" + sessionId));

        // 幂等：这题已经答过（用户连点、前端重试），不再推进进度
        if (question.getAnsweredAt() != null) {
            log.info("第 {} 题已作答，忽略重复提交: sessionId={}", index, sessionId);
            return currentOf(session, plan);
        }

        question.setAnswerText(answerText);
        question.setAnsweredAt(LocalDateTime.now());
        questionRepo.save(question);

        int next = index + 1;
        session.setCurrentQuestionIndex(next);

        if (next >= session.getTotalQuestions()) {
            finish(session);
        } else {
            // 下一题开始"被问到"了，补上时间戳
            questionRepo.findFirstBySessionIdAndQuestionIndex(sessionId, next)
                    .filter(q -> q.getAskedAt() == null)
                    .ifPresent(q -> {
                        q.setAskedAt(LocalDateTime.now());
                        questionRepo.save(q);
                    });
        }

        sessionRepo.save(session);
        log.info("已保存回答: sessionId={}, 题号={}, 下一题={}", sessionId, index, next);
        return currentOf(session, plan);
    }

    /** 整场问答回放（不评分） */
    @Transactional(readOnly = true)
    public SessionResultResponse result(Long sessionId) {
        InterviewSessionEntity session = loadSession(sessionId);
        List<InterviewQuestionEntity> questions =
                questionRepo.findBySessionIdOrderByQuestionIndexAsc(sessionId);

        List<SessionResultResponse.AnswerRecord> items = questions.stream()
                .map(q -> new SessionResultResponse.AnswerRecord(
                        q.getQuestionIndex(),
                        q.getCategoryKey(),
                        q.getQuestionText(),
                        q.getAnswerText(),
                        q.getAnsweredAt()))
                .toList();

        int answeredCount = (int) questions.stream()
                .filter(q -> q.getAnsweredAt() != null)
                .count();

        return new SessionResultResponse(
                session.getId(),
                session.getSkillId(),
                session.getStatus().name(),
                session.getTotalQuestions(),
                answeredCount,
                session.getFinishedAt(),
                items);
    }

    // ==================== 私有方法 ====================

    private InterviewSessionEntity loadSession(Long sessionId) {
        return sessionRepo.findById(sessionId)
                .orElseThrow(() -> new BusinessException(
                        ErrorCode.INTERVIEW_SESSION_NOT_FOUND, "面试会话不存在,id=" + sessionId));
    }

    /** 把会话的当前进度翻译成响应体 */
    private CurrentQuestionResponse currentOf(InterviewSessionEntity session, List<CategoryQuota> plan) {
        int index = session.getCurrentQuestionIndex();
        QuestionResponse question = null;

        if (session.getStatus() == InterviewSessionStatus.IN_PROGRESS
                && index < session.getTotalQuestions()) {
            question = questionRepo
                    .findFirstBySessionIdAndQuestionIndex(session.getId(), index)
                    .map(q -> toQuestionResponse(q, plan))
                    .orElse(null);
        }

        return new CurrentQuestionResponse(
                session.getId(),
                session.getStatus().name(),
                index,
                session.getTotalQuestions(),
                question);
    }

    private void finish(InterviewSessionEntity session) {
        session.setStatus(InterviewSessionStatus.COMPLETED);
        session.setFinishedAt(LocalDateTime.now());
    }

    private QuestionResponse toQuestionResponse(InterviewQuestionEntity q, List<CategoryQuota> plan) {
        return new QuestionResponse(
                q.getId(),
                q.getQuestionIndex(),
                q.getCategoryKey(),
                categoryLabels(plan).getOrDefault(q.getCategoryKey(), q.getCategoryKey()),
                q.getDifficulty() == null ? null : q.getDifficulty().name(),
                q.getQuestionText());
    }

    private Map<String, String> categoryLabels(List<CategoryQuota> plan) {
        Map<String, String> labels = new HashMap<>();
        for (CategoryQuota quota : plan) {
            labels.put(quota.categoryKey(), quota.label());
        }
        return labels;
    }

    private List<CategoryQuota> parsePlan(String json) {
        if (json == null || json.isBlank()) {
            return List.of();
        }
        try {
            return objectMapper.readValue(json, new TypeReference<List<CategoryQuota>>() {
            });
        } catch (JacksonException e) {
            log.warn("解析出题配额失败: {}", json);
            return List.of();
        }
    }
}
```

## 5.2 逐块解释

### ① 为什么 `answer` 这次可以加 `@Transactional`

M5-1 的 `generate` **故意不加**，因为它中间要等 AI 30 秒，包在事务里会一直占着数据库连接。

`answer` 完全相反：它只做两次数据库写，**几毫秒**。这种"纯数据库操作"就该放进事务，理由有两个：

1. **要么全成功，要么全失败**：如果"存回答"成功了但"推进进度"失败了，用户会卡在第 0 题上反复答同一题。
2. **一致性**：两个更新在同一个事务里，别的请求不会看到"回答存了但进度没动"的中间状态。

> 记忆方法：**事务里不要有网络调用**（HTTP、AI、发短信、读大文件）。有的话，把网络调用挪到事务外面。

### ② 幂等检查为什么放在"推进进度"之前

```
① 查出当前题
② 检查 answeredAt != null
     有值 → 这题答过了 → 直接返回当前状态，什么都不改
③ 才去改数据
```

如果顺序反过来（先改再检查），重复提交就会把进度推进两次。

**"先检查、后修改"是幂等的标准写法**：先判断这个操作是否已经做过。

### ③ 为什么重复提交返回"当前状态"而不是报错

假设用户手快点了两次：

```
第 1 次：answeredAt 是 null → 存回答 → 进度 0 → 1 → 返回第 1 题
第 2 次：answeredAt 有值   → 什么都不做 → 返回第 1 题
```

两次返回的都是"第 1 题"。**对前端来说，第二次请求"成功"了，而且拿到了它要的东西。**

如果第二次报错，前端就得处理"这是不是我的重复点击造成的错误"——这种判断非常难写，而且容易误导用户。

> 原则：**重复执行无害的操作，重复执行应该得到同样的结果**（这正是"幂等"的定义）。

### ④ `finish()` 为什么单独抽成一个方法

因为它被两处用到：

```
① 正常答完最后一题时
② 兜底的"进度越界但状态没改"时
```

抽出来保证两处行为完全一致（都设 `COMPLETED` + `finishedAt`）。

**重复的代码最好抽成方法，而不是复制粘贴** —— 因为将来如果"结束时还要多做一件事"（比如触发异步评分），只要改一个地方。

### ⑤ 为什么 `currentIndex` 在结束后等于 `totalQuestions`

答完第 9 题（共 10 题）时：

```
index = 9 → next = 10
session.currentQuestionIndex = 10
session.status = COMPLETED
```

于是 `currentIndex == totalQuestions` —— 前端进度条正好走满（10/10），不需要特殊处理"结束时进度条显示什么"。

**好的数据设计能让前端少写一个 if。**

# 第 6 部分：控制器

## 6.1 新建 `src/main/java/com/interviewmind/modules/interview/controller/InterviewAnswerController.java`

```java
package com.interviewmind.modules.interview.controller;

import com.interviewmind.common.result.Result;
import com.interviewmind.modules.interview.model.request.AnswerRequest;
import com.interviewmind.modules.interview.model.SessionResultResponse;
import com.interviewmind.modules.interview.service.InterviewAnswerService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.orm.ObjectOptimisticLockingFailureException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@Slf4j
@RestController
@RequestMapping("/api/interview/sessions")
@RequiredArgsConstructor
public class InterviewAnswerController {

    private final InterviewAnswerService answerService;

    /** 现在该答哪一题 */
    @GetMapping("/{id}/current")
    public Result<com.interviewmind.modules.interview.model.response.CurrentQuestionResponse> current(@PathVariable("id") Long id) {
        return Result.success(answerService.current(id));
    }

    /** 提交当前题的回答，直接返回下一题 */
    @PostMapping("/{id}/answers")
    public Result<com.interviewmind.modules.interview.model.response.CurrentQuestionResponse> answer(@PathVariable("id") Long id,
                                                                                                     @Valid @RequestBody AnswerRequest request) {
        try {
            return Result.success(answerService.answer(id, request.answerText()));
        } catch (ObjectOptimisticLockingFailureException e) {
            // 两个请求同时提交同一题：另一个已经推进了进度。
            // 这里在事务外面（控制器没有事务），所以 catch 是安全的。
            log.warn("并发提交同一题，返回最新状态: sessionId={}", id);
            return Result.success(answerService.current(id));
        }
    }

    /** 整场问答回放 */
    @GetMapping("/{id}/result")
    public Result<SessionResultResponse> result(@PathVariable("id") Long id) {
        return Result.success(answerService.result(id));
    }
}
```

## 6.2 为什么这个 catch 放在控制器里是安全的

这一条是整个 M5 里最微妙的地方，值得单独说。

**两个前提：**

1. `answerService.answer(...)` 上有 `@Transactional`，事务在这个方法**返回时**提交。提交时如果发现版本冲突，抛 `ObjectOptimisticLockingFailureException`。
2. **控制器本身没有事务**，所以异常抛到控制器时，那个失败的事务已经干干净净地回滚了。

**于是控制器可以放心地 catch，然后重新查一次数据库**。

对比 M5-1 的坑（**在事务内 catch 数据库异常 → 事务变成回滚态 → 后续查询报错**），差别在于"catch 的位置是否在事务边界之外"。

```
❌ 事务方法内部 catch → 事务已脏，不能再用
✅ 事务方法外部 catch → 事务已回滚干净，可以继续查
```

## 6.3 `@Valid` 为什么必须写

`AnswerRequest` 上的 `@NotBlank` / `@Size` **只是元数据**。不写 `@Valid`，Spring 不会去读它们，校验形同虚设。

写了 `@Valid` 之后，如果回答为空：

```
MethodArgumentNotValidException
→ 你在 M2 写的 GlobalExceptionHandler 接住
→ 返回 code=400, message="回答内容不能为空"
```

# 第 8 部分：常见错误

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 启动报 `missing column [answer_text]` | V5 没执行 | 检查文件名是 `V5__add_interview_answer.sql`（双下划线） |
| `currentIndex` 一直是 0 | 回答没保存成功，或事务回滚了 | 看日志有没有 `已保存回答` |
| 答一题 `currentIndex` 加了 2 | 幂等检查被跳过 | 检查 `answeredAt != null` 那段是否在改数据**之前** |
| 答完最后一题还是 `IN_PROGRESS` | `finish` 没被调用 | 检查 `next >= totalQuestions` 的分支 |
| `question` 一直是 null | `current_question_index` 大于等于 `total_questions` 了 | 查一下会话表的实际值 |
| 提交空回答返回 500 | 控制器方法忘了 `@Valid` | 加在 `@RequestBody` 参数上 |
| 并发时报 `ObjectOptimisticLockingFailureException` 冒到前端 | 控制器没 catch | 检查 catch 是否在控制器，而不是 Service 里 |
| `categoryLabel` 是 null | `plan_json` 解析失败 | 看日志里有没有 `解析出题配额失败` |
