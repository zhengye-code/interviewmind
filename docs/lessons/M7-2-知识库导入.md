# M7-2：把知识文档切成块，灌进向量库

> **本步目标**：现在向量库里只有 4 段硬编码的测试文字。这一步要让它变成**真正的知识库**：
>
> ```
> resources/knowledge/redis/cache-pitfalls.md   ← 一篇 600 字的文章
>        ↓ 切分
> 2 个块，每块 ≤ 500 字
>        ↓ 向量化（bge-m3）
> 存进 vector_store，metadata 里带上「来自哪篇、属于哪个分类、是第几块」
> ```
>
> 并且保证：**同一篇文档重复导入不会重复入库。**

---

# 第 0 部分：本步要做的事

```
① 切分        一篇文档 → N 个块
② 向量化      每个块 → 1024 个小数（由 bge-m3 完成）
③ 入库        写进 vector_store
④ 记录        knowledge_documents 表：这篇导过没有、切了几块
⑤ 检索        正式接口：按语义搜，可按分类过滤
```

# 第 1 部分：为什么必须切分

## 1.1 三个理由，一个比一个现实

**理由 1：embedding 有长度上限**

bge-m3 最多吃 8192 个 token。一篇 2 万字的文档塞不进去。

**理由 2：检索的粒度要匹配问题的粒度**

用户问的是"缓存击穿怎么防"，你期待的是**一段话**，不是"整本书"。

如果整篇文章只算一个向量，那这个向量代表的是"全文的平均含义"。检索出来时，你会拿到一大坨 2 万字的内容 —— 既塞不进提示词，也稀释了真正相关的部分。

**理由 3：一块里混多个主题，向量会"变糊"**

假设一个块里同时讲了"缓存穿透""MySQL 索引""HashMap 扩容"，它的向量就是这三个主题的**平均**。

结果：搜这三个中任何一个，它的相似度都不会很高。**块越杂，向量越糊，检索越差。**

> 所以切分的目标是：**一块只讲一件事。**

## 1.2 切多大

| 大小 | 好处 | 坏处 |
|---|---|---|
| 太小（< 100 字） | 向量很精确 | 上下文不足，一句话脱离上下文就没意义了 |
| **适中（300–800 字）** | 兼顾精确与完整 | — |
| 太大（> 1500 字） | 上下文完整 | 向量变糊，检索不准；prompt 变长 |

**本项目选 500 字**（按字符算，中文一个字大约等于一个 token 多一点）。

## 1.3 为什么要"重叠"（overlap）

假设原文是这样：

```
……击穿发生在热点键过期的瞬间，| 大量请求同时打到数据库……
                              ↑ 正好切在这里
```

不重叠的话：

- 第 1 块结尾："……击穿发生在热点键过期的瞬间，"
- 第 2 块开头："大量请求同时打到数据库……"

**第 2 块完全不知道自己在讲哪个主题** —— 它开头就是"大量请求"，没有主语。

重叠就是在第 2 块开头**重复上一块的末尾一小段**：

```
第 1 块：……击穿发生在热点键过期的瞬间，大量请求
第 2 块：击穿发生在热点键过期的瞬间，大量请求同时打到数据库……
        ↑ 这 50 字是重复的
```

**代价**：总字数变多（多花 embedding 的钱）。
**收益**：每个块都能独立看懂。

本项目选 **50 字重叠**（chunk size 的 10%）。

# 第 2 部分：幂等 —— 为什么不能"直接再导一次"

M7-1 你做过这个实验：`seed` 调两次，表里变成 8 行。

因为 `Document` 没指定 id，每次都是新 uuid。

**真实知识库这么干会出大问题**：

```
第 1 次导入：cache.md → 2 个块 → 表里 2 行
第 2 次导入：cache.md → 2 个块 → 表里 4 行  ← 同样的内容有 4 份

用户搜索"缓存击穿" → 返回 4 个几乎一样的结果
→ 塞进提示词 → 既浪费 token，又让模型"只看到这一篇"
```

**所以每篇文档要有"指纹"**：内容算 SHA-256。

```
指纹一样      → 内容没变，跳过（不花钱、不改库）
指纹不一样    → 内容改了，先删旧块的向量，再导入新的
```

SHA-256 是一种"内容指纹"算法：同样的输入永远得到同一个 64 位十六进制字符串，改一个字符结果就完全不同。

> 你在 M3 已经用过一次了（`FileHashService`，用来给上传的简历去重）。**同一套思路，换个场景。**

## 3.2 逐列解释

| 列 | 作用 | 为什么需要 |
|---|---|---|
| `source` | 来源路径，如 `knowledge/redis/cache-pitfalls.md` | **唯一**：一篇文档只有一条记录 |
| `title` | 从文件里第一个 `# 标题` 取 | 展示、追溯 |
| `category` | 目录名，如 `REDIS` | 检索时过滤（M7-3 用） |
| `content_hash` | 内容的 SHA-256 | **唯一**：内容没变就不重导 |
| `chunk_count` | 切成了几块 | 排障、展示 |
| `status` | `IMPORTING` / `READY` / `FAILED` | 失败能看出来 |
| `error_message` | 失败原因 | 不用翻日志 |
| `imported_at` / `updated_at` | 时间 | 常规 |

### 为什么 `source` 和 `content_hash` 都要唯一

两个约束管的是不同的事：

```
uk_knowledge_source  →  一篇文档只能有一条记录（改了内容也是同一条，更新它）
uk_knowledge_hash    →  两篇不同路径的文档，内容不能一模一样（防止重复导入同一个文件）
```

第二个约束比较"硬"：如果你把 `cache.md` 复制成 `cache-copy.md`，内容和它一模一样 → 第二个会被拒绝。这正是我们想要的（**同一份知识不要存两遍**）。

### `status` 为什么是 VARCHAR 而不是布尔

因为要区分三种状态：

```
IMPORTING  入库中（可能正在调 embedding，会持续几秒）
READY      已就绪，可以检索
FAILED     失败了，重试会覆盖
```

用 `boolean imported` 表达不了"正在导入"和"导入失败"的差别。

# 第 4 部分：切分器（纯函数，可单测）

## 4.1 算法思路

```
① 先按句子切开：遇到 。！？；或换行就断开
② 单句太长（超过 500 字）→ 硬切成 500 字一段
③ 贪心装箱：一句句往当前块里加，加不下了就封块
④ 封块时，把末尾 50 字带进下一块开头
```

**为什么以"句"为单位而不是"字"**：一句完整的话被切断，语义损失比"断在句子之间"大得多。

## 4.2 代码

`src/main/java/com/interviewmind/infrastructure/text/TextChunker.java`

```java
package com.interviewmind.infrastructure.text;

import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;
import java.util.regex.Pattern;

/**
 * 文本切分器：把一篇长文切成适合向量检索的小块。
 *
 * 三个参数：
 *   maxChars  每块最多多少字符
 *   overlap   相邻块之间重复多少字符
 *
 * 纯函数（不读数据库、不调网络），所以能直接写单元测试。
 */
@Component
public class TextChunker {

    private static final int DEFAULT_MAX_CHARS = 500;
    private static final int DEFAULT_OVERLAP = 50;

    /** 在句末标点之后断开，保留标点本身 */
    private static final Pattern SENTENCE_END = Pattern.compile("(?<=[。！？；.!?;\\n])");

    public List<String> chunk(String text) {
        return chunk(text, DEFAULT_MAX_CHARS, DEFAULT_OVERLAP);
    }

    public List<String> chunk(String text, int maxChars, int overlap) {
        if (text == null) {
            return List.of();
        }
        String normalized = text.replace("\r\n", "\n").trim();
        if (normalized.isEmpty()) {
            return List.of();
        }

        // 防止参数写错导致死循环或块过大
        int effectiveMax = Math.max(50, maxChars);
        int effectiveOverlap = Math.max(0, Math.min(overlap, effectiveMax / 4));

        List<String> chunks = new ArrayList<>();
        StringBuilder current = new StringBuilder();

        for (String piece : splitIntoSentences(normalized)) {
            for (String part : hardSplit(piece, effectiveMax)) {
                if (current.length() > 0 && current.length() + part.length() > effectiveMax) {
                    String finished = current.toString().trim();
                    if (!finished.isEmpty()) {
                        chunks.add(finished);
                    }
                    // 把结尾一小段带到下一块开头
                    String tail = tailOf(finished, effectiveOverlap);
                    current.setLength(0);
                    current.append(tail);
                }
                current.append(part);
            }
        }

        String last = current.toString().trim();
        if (!last.isEmpty()) {
            chunks.add(last);
        }
        return chunks;
    }

    /** 按句末标点切，去掉空串 */
    private List<String> splitIntoSentences(String text) {
        List<String> pieces = new ArrayList<>();
        for (String raw : SENTENCE_END.split(text)) {
            if (raw != null && !raw.isBlank()) {
                pieces.add(raw);
            }
        }
        return pieces;
    }

    /** 单句超过上限时硬切 */
    private List<String> hardSplit(String piece, int maxChars) {
        if (piece.length() <= maxChars) {
            return List.of(piece);
        }
        List<String> parts = new ArrayList<>();
        for (int start = 0; start < piece.length(); start += maxChars) {
            parts.add(piece.substring(start, Math.min(piece.length(), start + maxChars)));
        }
        return parts;
    }

    private String tailOf(String text, int count) {
        if (text == null || text.isEmpty() || count <= 0) {
            return "";
        }
        int start = Math.max(0, text.length() - count);
        return text.substring(start);
    }
}
```

### 几个细节

**① 为什么要 `Math.max(50, maxChars)` 和 `Math.min(overlap, maxChars/4)`**

防呆。如果有人传 `chunk(text, 10, 8)`，那么 overlap 8 几乎等于 maxChars 10 —— 每次封块后新块一开头就占了 8 个字，只剩 2 个字的空间，会切出无数细碎的块。

**把 overlap 限制在 maxChars 的 1/4 以内**，保证每块至少有 3/4 是"新内容"。

**② 为什么 `hardSplit` 放在内层**

因为一句 800 字的"句子"（比如没有标点的一大段）也必须能处理。先按句子切是为了语义完整，硬切是最后兜底。

**③ 为什么返回 `List.copyOf` 风格的不可变列表**

这里返回的是 `ArrayList`（可变）。如果你希望更严格可以改成 `List.copyOf(chunks)`。当前无害，因为调用方只是读。

# 第 5 部分：切分器的单元测试

`src/test/java/com/interviewmind/infrastructure/text/TextChunkerTest.java`

```java
package com.interviewmind.infrastructure.text;

import org.junit.jupiter.api.Test;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;

class TextChunkerTest {

    private final TextChunker chunker = new TextChunker();

    @Test
    void 空文本切出零块() {
        assertThat(chunker.chunk(null)).isEmpty();
        assertThat(chunker.chunk("")).isEmpty();
        assertThat(chunker.chunk("   \n  ")).isEmpty();
    }

    @Test
    void 短文本只有一块() {
        String text = "Redis 缓存击穿是指热点键过期瞬间，大量请求打到数据库。";

        List<String> chunks = chunker.chunk(text);

        assertThat(chunks).hasSize(1);
        assertThat(chunks.get(0)).isEqualTo(text);
    }

    @Test
    void 长文本会被切成多块且不超过上限加重叠() {
        String sentence = "这是一句话，用来填充长度，检验切分是否正确。";
        String text = sentence.repeat(60);   // 约 1440 字

        List<String> chunks = chunker.chunk(text, 200, 20);

        assertThat(chunks).hasSizeGreaterThan(1);
        assertThat(chunks).allSatisfy(chunk -> assertThat(chunk.length()).isLessThanOrEqualTo(220));
    }

    @Test
    void 相邻块之间有重叠() {
        String text = "第一句内容。第二句内容。第三句内容。第四句内容。第五句内容。第六句内容。";

        List<String> chunks = chunker.chunk(text, 20, 5);

        assertThat(chunks).hasSizeGreaterThan(1);
        String tailOfFirst = chunks.get(0).substring(chunks.get(0).length() - 5);
        assertThat(chunks.get(1)).startsWith(tailOfFirst);
    }

    @Test
    void 没有标点的超长文本会被硬切() {
        String text = "一".repeat(1200);

        List<String> chunks = chunker.chunk(text, 300, 0);

        assertThat(chunks).hasSize(4);          // 1200 / 300
        assertThat(chunks).allSatisfy(chunk -> assertThat(chunk.length()).isLessThanOrEqualTo(300));
    }

    @Test
    void 切分后内容不丢字() {
        String text = "甲。乙。丙。丁。戊。己。庚。辛。壬。癸。";

        List<String> chunks = chunker.chunk(text, 8, 0);

        String joined = String.join("", chunks);
        assertThat(joined).isEqualTo(text.replace("\r\n", "\n").trim());
    }
}
```

### 最后那个测试为什么重要

`切分后内容不丢字` —— 它验证"把块拼回去等于原文"（overlap=0 时成立）。

这是**切分算法最基本的正确性**：任何切分都不该**丢内容**。如果这个测试挂了，说明某处 `substring` 算错了，用户的文档会悄悄缺一段 —— 这种 bug 在检索层面极难发现（因为检索"看起来正常"，只是有时候搜不到）。

> **纯函数的价值就在这**：6 个测试 1 秒跑完，覆盖 6 种边界情况。用接口测要导入 6 次文档、每次还要调 embedding API。

    public String sha256Hex(String text) {
        try {
            MessageDigest digest = MessageDigest.getInstance(ALGORITHM);
            return HexFormat.of().formatHex(digest.digest(text.getBytes(StandardCharsets.UTF_8)));
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException("SHA-256 不可用", e);
        }
    }

    @Enumerated(EnumType.STRING)
    @Column(name = "status", nullable = false, length = 20)
    private KnowledgeImportStatus status = KnowledgeImportStatus.IMPORTING;

    @Column(name = "error_message", length = 500)
    private String errorMessage;

    @Column(name = "imported_at", nullable = false)
    private LocalDateTime importedAt;

    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;

    @PrePersist
    protected void onCreate() {
        LocalDateTime now = LocalDateTime.now();
        if (importedAt == null) {
            importedAt = now;
        }
        updatedAt = now;
    }

    @PreUpdate
    protected void onUpdate() {
        updatedAt = LocalDateTime.now();
    }
}

# 第 8 部分：导入服务

```java
package com.interviewmind.modules.interview.service;

import com.interviewmind.infrastructure.file.FileHashService;
import com.interviewmind.infrastructure.text.TextChunker;
import com.interviewmind.modules.interview.model.KnowledgeDocumentEntity;
import com.interviewmind.modules.interview.model.KnowledgeImportStatus;
import com.interviewmind.modules.interview.repository.KnowledgeDocumentRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.filter.Filter;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;
import org.springframework.core.io.Resource;
import org.springframework.core.io.support.PathMatchingResourcePatternResolver;
import org.springframework.core.io.support.ResourcePatternResolver;
import org.springframework.stereotype.Service;

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;

/**
 * 知识库导入：扫 classpath 下的 knowledge/分类/xxx.md，
 * 切块 → 向量化 → 写进 vector_store，并登记到 knowledge_documents。
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class KnowledgeImportService {

    private static final String KNOWLEDGE_GLOB = "classpath*:knowledge/*/*.md";
    private static final Pattern SOURCE_PATTERN = Pattern.compile(".*/knowledge/([^/]+)/([^/]+)\\.md$");
    private static final Pattern TITLE_PATTERN = Pattern.compile("(?m)^#\\s+(.+)$");

    private final VectorStore vectorStore;
    private final KnowledgeDocumentRepository documentRepo;
    private final FileHashService fileHashService;
    private final TextChunker textChunker;
    private final ResourcePatternResolver resourceResolver = new PathMatchingResourcePatternResolver();

    /** 导入结果汇总 */
    public record ReindexResult(int imported, int skipped, int failed, int totalChunks) {
    }

    /**
     * 扫描并导入。
     *
     * @param force true 表示忽略内容指纹，全部重新导入
     */
    public ReindexResult reindex(boolean force) {
        Resource[] resources;
        try {
            resources = resourceResolver.getResources(KNOWLEDGE_GLOB);
        } catch (IOException e) {
            throw new IllegalStateException("扫描知识库目录失败", e);
        }

        int imported = 0;
        int skipped = 0;
        int failed = 0;
        int totalChunks = 0;

        for (Resource resource : resources) {
            SourceInfo info = parseSource(resource);
            if (info == null) {
                log.warn("无法解析知识文件路径，跳过: {}", resource.getDescription());
                continue;
            }

            try {
                ImportOutcome outcome = importOne(resource, info, force);
                switch (outcome) {
                    case SKIPPED -> skipped++;
                    case IMPORTED -> imported++;
                }
                if (outcome == ImportOutcome.IMPORTED) {
                    totalChunks += documentRepo.findBySource(info.source())
                            .map(KnowledgeDocumentEntity::getChunkCount)
                            .orElse(0);
                }
            } catch (Exception e) {
                failed++;
                log.error("知识文件导入失败: {}", info.source(), e);
            }
        }

        log.info("知识库导入完成: 新导入={}, 跳过={}, 失败={}, 新增块={}",
                imported, skipped, failed, totalChunks);
        return new ReindexResult(imported, skipped, failed, totalChunks);
    }

    private enum ImportOutcome { IMPORTED, SKIPPED }

    private ImportOutcome importOne(Resource resource, SourceInfo info, boolean force) throws IOException {
        String text = resource.getContentAsString(StandardCharsets.UTF_8);
        String hash = fileHashService.sha256Hex(text);

        KnowledgeDocumentEntity existing = documentRepo.findBySource(info.source()).orElse(null);

        // 内容没变、且上次成功了 → 跳过
        if (!force && existing != null
                && hash.equals(existing.getContentHash())
                && existing.getStatus() == KnowledgeImportStatus.READY) {
            log.info("内容未变化，跳过: {}", info.source());
            return ImportOutcome.SKIPPED;
        }

        // 内容变了（或强制重导）→ 先清掉旧向量
        if (existing != null) {
            deleteVectors(existing.getId());
            documentRepo.delete(existing);
        }

        KnowledgeDocumentEntity document = existing != null ? existing : new KnowledgeDocumentEntity();
        document.setSource(info.source());
        document.setCategory(info.category());
        document.setTitle(extractTitle(text, info.filename()));
        document.setContentHash(hash);
        document.setChunkCount(0);
        document.setStatus(KnowledgeImportStatus.IMPORTING);
        document.setErrorMessage(null);
        document = documentRepo.save(document);

        try {
            List<String> chunks = textChunker.chunk(text);
            if (chunks.isEmpty()) {
                throw new IllegalStateException("切分后没有任何内容");
            }

            List<Document> documents = new ArrayList<>(chunks.size());
            for (int index = 0; index < chunks.size(); index++) {
                Map<String, Object> metadata = new HashMap<>();
                metadata.put("documentId", String.valueOf(document.getId()));
                metadata.put("source", info.source());
                metadata.put("category", info.category());
                metadata.put("title", document.getTitle());
                metadata.put("chunkIndex", index);
                documents.add(new Document(chunks.get(index), metadata));
            }

            vectorStore.add(documents);

            document.setChunkCount(chunks.size());
            document.setStatus(KnowledgeImportStatus.READY);
            documentRepo.save(document);

            log.info("已导入 {} → {} 块", info.source(), chunks.size());
            return ImportOutcome.IMPORTED;

        } catch (Exception e) {
            document.setStatus(KnowledgeImportStatus.FAILED);
            document.setErrorMessage(truncate(e.getMessage()));
            documentRepo.save(document);
            throw e;
        }
    }

    /** 删除某篇文档之前写入的所有向量 */
    private void deleteVectors(Long documentId) {
        Filter.Expression expression = new FilterExpressionBuilder()
                .eq("documentId", String.valueOf(documentId))
                .build();
        vectorStore.delete(expression);
        log.info("已清理旧向量: documentId={}", documentId);
    }

    private record SourceInfo(String source, String category, String filename) {
    }

    private SourceInfo parseSource(Resource resource) {
        try {
            String url = resource.getURL().toString().replace('\\', '/');
            Matcher matcher = SOURCE_PATTERN.matcher(url);
            if (!matcher.find()) {
                return null;
            }
            String category = matcher.group(1).toUpperCase();
            String filename = matcher.group(2);
            return new SourceInfo("knowledge/" + matcher.group(1) + "/" + filename + ".md", category, filename);
        } catch (IOException e) {
            return null;
        }
    }

    private String extractTitle(String text, String fallback) {
        Matcher matcher = TITLE_PATTERN.matcher(text);
        if (matcher.find()) {
            return matcher.group(1).trim();
        }
        return fallback;
    }

    private String truncate(String message) {
        if (message == null) {
            return null;
        }
        return message.length() <= 500 ? message : message.substring(0, 500);
    }
}
```

### 逐块解释

**① 为什么用 `classpath*:knowledge/*/*.md`**

和 M4-1 扫 `skills` 用的是同一套技术（`PathMatchingResourcePatternResolver`）。

`*/` 匹配"分类目录"，所以 `knowledge/redis/cache.md` 的 category 就是 `REDIS`。

**为什么要把分类放在目录结构里**：因为 M7-3 检索时要按题目的分类过滤（评分 MySQL 题时只检索 MySQL 知识）。**目录结构本身就成了分类信息**，不用在文件里手写 front matter。

**② 为什么"内容变了"要删旧向量**

如果只更新记录、不删旧向量，库里会同时存在同一个文档的**新旧两版**块。搜出来的结果一半是过期知识。

`deleteVectors` 靠 metadata 里的 `documentId` 找到那批向量删掉 —— **这就是为什么每个块的 metadata 里必须存 `documentId`**。

**③ 为什么 `documentId` 存成 String**

pgvector 的 metadata 是一个 JSON 列。用数字比较时，不同版本的 SQL 生成会有细节差异（`1` vs `'1'`）。**统一用字符串比较最稳**。

**④ 为什么先 `save(IMPORTING)`，最后再 `save(READY)`**

因为 `vectorStore.add` 要调 embedding API，可能失败。

- 如果先插入记录，中途失败 → 记录停留在 `IMPORTING` 或变成 `FAILED` → **你能查到"这篇没导成功"**
- 如果等所有事都做完才插入记录，中途失败 → 数据库里什么都没有 → **但向量可能已经写进去了一部分** → 你完全不知道留下了脏数据

**先登记、再干活、最后改状态** —— 这是所有"有外部副作用的任务"的标准写法（你在 M3 的简历分析里见过一遍）。

**⑤ 为什么失败用 `catch` 包住每个文件，而不是整个方法**

一个文件坏掉，不该让其他文件也导不进去。**故障隔离**。

**⑥ `switch (outcome)` 那段有个小坑**

```java
switch (outcome) {
    case SKIPPED -> skipped++;
    case IMPORTED -> imported++;
}
```

这两个分支和下面 `if (outcome == ImportOutcome.IMPORTED)` 有点重复。可以合并成：

```java
if (outcome == ImportOutcome.SKIPPED) {
    skipped++;
} else {
    imported++;
    totalChunks += documentRepo.findBySource(info.source())
            .map(KnowledgeDocumentEntity::getChunkCount).orElse(0);
}
```

**更简洁。** 上面代码里保留 switch 只是为了让你看到两种写法都行 —— 实际写的时候用下面这个。

`src/main/java/com/interviewmind/modules/interview/controller/KnowledgeController.java`

```java
package com.interviewmind.modules.interview.controller;

import com.interviewmind.common.result.Result;
import com.interviewmind.modules.interview.model.KnowledgeDocumentEntity;
import com.interviewmind.modules.interview.repository.KnowledgeDocumentRepository;
import com.interviewmind.modules.interview.service.KnowledgeImportService;
import lombok.RequiredArgsConstructor;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.filter.Filter;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/api/knowledge")
@RequiredArgsConstructor
public class KnowledgeController {

    private final KnowledgeImportService importService;
    private final KnowledgeDocumentRepository documentRepo;
    private final VectorStore vectorStore;

    /** 检索结果 */
    public record KnowledgeHit(String text, Double score, String title,
                               String category, Integer chunkIndex) {
    }

    /** 扫描并导入知识文档；force=true 强制全量重导 */
    @PostMapping("/reindex")
    public Result<KnowledgeImportService.ReindexResult> reindex(
            @RequestParam(value = "force", defaultValue = "false") boolean force) {
        return Result.success(importService.reindex(force));
    }

    /** 看知识库里有哪些文档 */
    @GetMapping("/documents")
    public Result<List<KnowledgeDocumentEntity>> documents() {
        return Result.success(documentRepo.findAllByOrderByIdAsc());
    }

    /** 按语义检索，可按分类过滤 */
    @GetMapping("/search")
    public Result<List<KnowledgeHit>> search(
            @RequestParam("q") String query,
            @RequestParam(value = "category", required = false) String category,
            @RequestParam(value = "topK", defaultValue = "3") int topK) {

        SearchRequest.Builder builder = SearchRequest.builder()
                .query(query)
                .topK(topK)
                .similarityThreshold(0.5);          // 低于 0.5 的直接丢掉

        if (category != null && !category.isBlank()) {
            Filter.Expression expression = new FilterExpressionBuilder()
                    .eq("category", category.toUpperCase())
                    .build();
            builder.filterExpression(expression);
        }

        List<Document> documents = vectorStore.similaritySearch(builder.build());

        List<KnowledgeHit> hits = new ArrayList<>();
        if (documents != null) {
            for (Document document : documents) {
                hits.add(new KnowledgeHit(
                        document.getText(),
                        document.getScore(),
                        String.valueOf(document.getMetadata().get("title")),
                        String.valueOf(document.getMetadata().get("category")),
                        (Integer) document.getMetadata().get("chunkIndex")));
            }
        }
        return Result.success(hits);
    }
}
```

### 两个设计点

**① `similarityThreshold(0.5)` 终于用上了**

M7-1 里说过：向量检索**永远返回 topK 条**，哪怕全不相关。

这里加了 0.5 的阈值，**不相关的直接不返回**。这样 M7-3 把结果拼进提示词时，就不会塞进垃圾。

**这个 0.5 是经验值**，要看你的实际数据调整：如果发现该搜到的没搜到，就调低；如果发现无关内容混进来，就调高。

**② `filterExpression` 用 Builder，不用字符串拼接**

```java
// ❌ 不要这样
builder.filterExpression("category == '" + category + "'");

// ✅ 这样
new FilterExpressionBuilder().eq("category", category).build()
```

**为什么**：字符串拼接有注入风险（虽然这里的 category 来自我们自己，但养成习惯）。Builder 会做正确的转义。

# Redis 缓存的三个典型故障

## 缓存穿透

缓存穿透是指查询一个缓存和数据库里都不存在的键。

因为两次都查不到，请求会穿过缓存直接落到数据库。攻击者可以构造大量不存在的键，把数据库打垮。

常见方案有两种：一是布隆过滤器，在缓存前面加一层「这个键是否存在」的判断，不存在直接返回；二是把空结果也缓存起来，设一个较短的过期时间。

布隆过滤器的代价是有误判率，而且删除元素比较麻烦；缓存空值实现简单，但要防止随机键把缓存写满。

## 缓存击穿

缓存击穿是指某个热点键在过期的瞬间，大量并发请求同时发现缓存失效，于是一起去查数据库。

它和穿透的区别是：穿透查的是本来就不存在的数据，击穿查的是真实存在的热点数据，只是那一刻缓存恰好没了。

常见方案有两种：一是互斥锁，只让第一个请求去加载数据，其他请求等待；二是逻辑过期，缓存里不设物理过期时间，而是存一个逻辑过期标记，发现过期后异步刷新，先返回旧值。

## 缓存雪崩

缓存雪崩是指大量键在同一时间集中过期，或者缓存服务整体不可用，导致所有请求涌向数据库。

和击穿的区别在规模：击穿是单个热点键，雪崩是一大批键或整个缓存层。

常见方案是在过期时间上加随机扰动，把过期时间分散开；以及做缓存高可用，例如主从加哨兵或集群模式。
```

# InnoDB 索引原理

## 为什么用 B+ 树而不是 B 树

B+ 树的非叶子节点只存键，不存数据，所以一个页能放更多键，扇出更大，树的层数更少。

层数少意味着查一次记录需要读的页更少，磁盘 I/O 更少。B 树的非叶子节点要存数据，扇出小，树更高。

另外 B+ 树的叶子节点之间用双向链表连接，范围查询只要定位到左端点然后顺着链表扫，而 B 树需要中序遍历。

## 聚簇索引与二级索引

InnoDB 的主键索引是聚簇索引，叶子节点直接存整行数据。一张表只能有一个聚簇索引。

其他索引是二级索引，叶子节点存的是主键值而不是行数据。所以通过二级索引查不在索引里的列时，需要先拿到主键，再回主键索引取整行，这个动作叫回表。

减少回表的方式是覆盖索引：让查询需要的列全部包含在二级索引里，这样就不需要回表。

## 最左前缀原则

联合索引（a, b, c）在 B+ 树里先按 a 排，a 相同再按 b 排，b 相同再按 c 排。

所以查询条件必须从最左列开始连续匹配才能用上索引：a、a+b、a+b+c 都可以，单独的 b 或 b+c 不行。

范围查询会中断后续列的使用：如果 a 用等值条件、b 用范围条件，那么 c 就无法继续利用索引顺序。
```

# HashMap 的实现要点

## 数据结构

JDK 8 之后 HashMap 是数组加链表加红黑树的组合。

数组的每个位置叫桶，哈希冲突时同一个桶里的元素用链表串起来。当链表长度达到 8 且数组长度达到 64 时，链表会转成红黑树，把最坏情况的查找从 O(n) 降到 O(log n)。

## 扩容机制

HashMap 的容量始终保持 2 的幂，默认是 16。扩容时容量翻倍。

保持 2 的幂是为了用位运算代替取模：当 n 是 2 的幂时，hash 与 n-1 做按位与，结果等价于 hash 对 n 取模，但位运算更快。

扩容后元素的位置只有两种可能：留在原下标，或者移动到原下标加旧容量的位置。判断依据是 hash 与旧容量那一位是 0 还是 1。

## 线程安全问题

HashMap 不是线程安全的，并发扩容可能造成数据丢失。

多线程场景应该使用 ConcurrentHashMap，它通过 CAS 配合桶级别的加锁来控制并发，读操作基本无锁。

JDK 7 的 HashMap 在并发扩容时可能形成环形链表导致死循环，JDK 8 改成尾插法后不再有死循环，但仍然会丢数据。
```
