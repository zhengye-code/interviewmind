# M7-1：把向量库接上 —— RAG 的地基

> **本步目标**：让你现有的 PostgreSQL 变成"能按语义搜索"的数据库。
>
> 做完之后你能做到这件事：
>
> ```
> 存 4 段文字进去
> 搜 "热点 key 过期后大量请求打到数据库"
> → 它返回"缓存击穿"那一段，而不是"缓存穿透"
> ```
>
> **注意：这时候还没有任何 AI 参与生成。** 只是"存进去、搜出来"。

# 第 1 部分：三个必须搞懂的概念

## 1.1 什么是 embedding（向量化）

**一句话**：把一段文字变成一串小数。

```
"Redis 缓存击穿"  →  [0.021, -0.134, 0.556, ... ]   一共 1024 个小数
```

**关键性质**：意思相近的文字，变成的数字也相近。

```
"Redis 缓存击穿"                          →  [0.021, -0.134, 0.556, ...]
"热点 key 过期导致大量请求打到数据库"      →  [0.019, -0.130, 0.561, ...]   ← 很像
"红烧肉要先焯水再炒糖色"                  →  [-0.412, 0.887, 0.023, ...]   ← 完全不同
```

**为什么需要它**：程序不懂"意思相近"。你没法写 `WHERE 意思 LIKE 'Redis 缓存击穿'`。但变成数字之后，就能用**数学**算两组数字有多接近。

这个"算接近"的数学叫**余弦相似度**：就是算两个向量的夹角。夹角越小越相似，结果落在 0 到 1 之间（1 表示完全一样）。

## 1.2 什么是向量库

普通数据库查的是"精确匹配"：

```sql
SELECT * FROM docs WHERE title = 'Redis 缓存击穿'
```

向量库查的是"**最接近的 K 个**"：

```
给我找出和这句话意思最接近的 3 段
```

它内部做的就是：把查询也变成向量，然后跟表里每一行算余弦相似度，排序，取前 K 个。

## 1.3 好消息：你已经有一个向量库了

**不用装任何新数据库。**

你的 PostgreSQL 镜像本来就是 `pgvector/pgvector:pg16`，`docker/postgres/init.sql` 里也已经写了：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

这个 `vector` 扩展给 Postgres 加了一种新类型：`vector(1024)` —— 一个能存 1024 个小数、并且能算相似度的列。

所以"向量库"就是**你现有的 Postgres 里多一张表**。

> 这就是 M0 时为什么特意选了 `pgvector/pgvector` 镜像而不是官方 `postgres`。当时注释写的"参考项目的向量检索依赖 pgvector 扩展"，现在派上用场了。

# 第 2 部分：缺的那块 —— embedding 从哪来

Postgres 能**存**向量、能**比较**向量，但**不能把文字变成向量**。

```
Postgres：  vector ✅   相似度计算 ✅   文字→向量 ❌
```

"文字→向量"必须调用一个**embedding 模型**。DeepSeek 没有这个接口，所以我们用**硅基流动**的 `BAAI/bge-m3`。

## 2.1 为什么是 bge-m3

| 特性 | 说明 |
|---|---|
| 中文强 | BAAI 是智源的模型，中文语料训练充分 |
| 1024 维 | 不算太大，存起来便宜 |
| 免费额度 | 学习够用 |
| OpenAI 兼容接口 | **不用加新依赖**，你 pom 里已有 `spring-ai-starter-model-openai` |

## 2.2 你要做的准备（5 分钟）

1. 打开 https://cloud.siliconflow.cn ，注册登录
2. 在"API 密钥"页面创建一个 key（形如 `sk-xxxx`）
3. 把它设成环境变量 **`EMBEDDING_API_KEY`**

```powershell
# 只对当前窗口有效（调试用）
$env:EMBEDDING_API_KEY = "sk-你的key"

# 或者设成用户环境变量（推荐，重开终端后一直有效）
[Environment]::SetEnvironmentVariable('EMBEDDING_API_KEY', 'sk-你的key', 'User')
```

> **不要把 key 直接写进 `application.properties`**。这个项目从 M2 开始就用环境变量管 key，文件是会提交到 git 的。

## 2.3 顺便让启动脚本也认得它

`scripts/run-dev.ps1` 现在只加载 `DEEPSEEK_API_KEY`。在它后面补一块（照抄 DeepSeek 那段的结构）：

```powershell
# ---- 确保 EMBEDDING_API_KEY 在当前进程可见 ----
if ([string]::IsNullOrWhiteSpace($env:EMBEDDING_API_KEY)) {
    $fromSystem = [Environment]::GetEnvironmentVariable('EMBEDDING_API_KEY', 'Machine')
    if ([string]::IsNullOrWhiteSpace($fromSystem)) {
        $fromSystem = [Environment]::GetEnvironmentVariable('EMBEDDING_API_KEY', 'User')
    }
    if (-not [string]::IsNullOrWhiteSpace($fromSystem)) {
        $env:EMBEDDING_API_KEY = $fromSystem
        Write-Host "已从系统环境变量载入 EMBEDDING_API_KEY（末4位: $($fromSystem.Substring($fromSystem.Length - 4))）" -ForegroundColor Cyan
    }
}
```

> ⚠️ 这个文件必须保持 **UTF-8 带 BOM**，否则 PowerShell 5.1 会报"字符串缺少终止符"。你 M2 踩过这个坑。

# 第 3 部分：改 pom 和配置

## 3.1 加一个依赖

`pom.xml` 的 `<dependencies>` 里，`spring-ai-starter-model-openai` 附近加：

```xml
        <!-- pgvector 向量库：让 Postgres 支持按语义检索 -->
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-starter-vector-store-pgvector</artifactId>
        </dependency>
```

**不用写版本号** —— 你 pom 里已经有 `spring-ai-bom`，版本由它统一管。

**这个依赖带来三样东西**：

| 东西 | 作用 |
|---|---|
| `spring-ai-vector-store` | `VectorStore` 接口（你要用的就是它） |
| `spring-ai-pgvector-store` | 针对 Postgres 的实现 |
| autoconfigure | 启动时自动创建 `VectorStore` 这个 Bean |

## 3.2 改 `application.properties`

### ① 打开 embedding

把这一行：

```properties
spring.ai.model.embedding=none
```

改成：

```properties
# 硅基流动（OpenAI 兼容接口）提供 embedding；chat 仍然是 deepseek
spring.ai.model.embedding=openai
spring.ai.openai.base-url=https://api.siliconflow.cn
spring.ai.openai.api-key=${EMBEDDING_API_KEY}
spring.ai.openai.embedding.options.model=BAAI/bge-m3
```

**逐行解释**：

| 配置 | 作用 |
|---|---|
| `spring.ai.model.embedding=openai` | 启用 openai 这家的**向量**模型自动装配（chat 不受影响，仍是 deepseek） |
| `spring.ai.openai.base-url` | **关键**：把 OpenAI 的地址换成硅基流动的地址 |
| `spring.ai.openai.api-key` | 从环境变量取 |
| `...embedding.options.model` | 指定用哪个向量模型 |

**最妙的是第二行**：硅基流动的接口就是"OpenAI 格式"，所以只要**换个地址**，Spring AI 的 OpenAI 客户端就直接能用。**一行配置接入一家新厂商。**

> 这就是 M0 时选"统一 OpenAI 协议"的回报。将来换百炼、换智谱，也是改这一行。

⚠️ **如果报 404**：把 `base-url` 改成 `https://api.siliconflow.cn/v1` 再试。不同版本对路径拼接的处理略有差异。

### ② 配 pgvector

接在上面这段后面：

```properties
# ---------- pgvector 向量库 ----------
# 表由 Flyway 建（V7），不让 Spring AI 自己建，避免两套建表工具打架
spring.ai.vectorstore.pgvector.initialize-schema=false
# 维度必须和 embedding 模型一致：bge-m3 是 1024
spring.ai.vectorstore.pgvector.dimensions=1024
spring.ai.vectorstore.pgvector.table-name=vector_store
# HNSW 是较新的近似索引；数据量少时用不用都行
spring.ai.vectorstore.pgvector.index-type=HNSW
# 余弦距离：比较的是"方向"，适合文本
spring.ai.vectorstore.pgvector.distance-type=COSINE_DISTANCE
```

**为什么 `initialize-schema=false`**：

Spring AI 默认会自己去建表。但你的项目用 **Flyway** 管表结构 —— 两个工具都建表会打架（Spring AI 建的和 Flyway 建的可能不一致，而且它可能尝试 drop 重建）。

**规矩：表结构只有一个主人。** 这里主人是 Flyway。

**为什么 `dimensions=1024` 必须和模型一致**：

```
bge-m3 输出 → 1024 个小数
表定义 → vector(1024)
```

如果表是 `vector(1536)` 但模型给 1024 个，插入直接报错：

```
ERROR: expected 1536 dimensions, not 1024
```

## 3.3 顺便把测试环境隔离好（重要）

加了 pgvector 依赖之后，**跑单元测试会炸**，因为：

1. 测试用的是 **H2 内存库**，H2 **没有** pgvector 扩展
2. Spring AI 会在测试里也尝试创建 `VectorStore` Bean → 连不上 / 建不了表

所以 `src/test/resources/application-test.properties` 里加上两行：

```properties
# 测试环境：不启用 embedding，也不装配 pgvector 向量库（H2 没有 vector 类型）
spring.ai.model.embedding=none
spring.autoconfigure.exclude=org.springframework.ai.vectorstore.pgvector.autoconfigure.PgVectorStoreAutoConfiguration
```

**第一行**：没有 embedding 模型，就不会去调外部 API（测试不该联网）
**第二行**：直接把 pgvector 的自动装配排除掉，测试上下文就不会去碰它

> `spring.autoconfigure.exclude` 的意思是"启动时跳过这些自动配置类"。它接受全类名，逗号分隔。

**不加这两行的后果**：`DemoApplicationTests` 启动失败，报一堆看不懂的驱动错误。**先加，省得后面排查。**

# 第 4 部分：迁移脚本 V7

`src/main/resources/db/migration/V7__add_vector_store.sql`

```sql
-- V7: 向量库表（pgvector）
-- 表结构必须和 Spring AI 的 PgVectorStore 约定一致：4 个列，名字固定

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS vector_store (
    id         uuid DEFAULT gen_random_uuid() PRIMARY KEY,
    content    text,
    metadata   json,
    embedding  vector(1024)
);

-- 近似最近邻索引：数据多了之后检索才不会全表扫描
CREATE INDEX IF NOT EXISTS idx_vector_store_embedding
    ON vector_store USING hnsw (embedding vector_cosine_ops);
```

## 逐行解释

**`CREATE EXTENSION IF NOT EXISTS vector`**

启用 pgvector 扩展。`IF NOT EXISTS` 保证重复执行不报错。

> 你的 `docker/postgres/init.sql` 已经在容器首次初始化时执行过一次了。这里再写一遍是**为了"从零重建数据库"时也能跑通**（比如换台机器、或者 `docker compose down -v` 清空数据卷）。**迁移脚本必须能独立跑**，不能依赖某个容器初始化脚本。

**4 个列的名字不能改**

Spring AI 的 `PgVectorStore` 写死了这几列：

| 列 | 类型 | 存什么 |
|---|---|---|
| `id` | uuid | 主键，Spring AI 自动生成 |
| `content` | text | 原始文字 |
| `metadata` | json | 附加信息（来源文件名、章节等） |
| `embedding` | vector(1024) | 向量 |

改名字 → 插入时报 `column "xxx" does not exist`。

**`vector(1024)` 里的 1024**

和 `spring.ai.vectorstore.pgvector.dimensions=1024`、以及 `bge-m3` 的输出维度**三处必须一致**。

**`USING hnsw (embedding vector_cosine_ops)`**

HNSW 是一种"近似最近邻"索引。它的作用是：数据多的时候，不用把每一行都算一遍，而是走图结构快速找到近似的候选。

| 索引 | 适合 |
|---|---|
| 无索引 | 几千行以内，全表扫描也就几毫秒 |
| HNSW | 几万行以上，查询快但建索引慢、占内存 |
| IVFFlat | 数据量大且写入频繁 |

现在数据少，建不建都行，但**提前建好，以后导入大文档不用改代码**。

`vector_cosine_ops` 必须和 `distance-type=COSINE_DISTANCE` 对应。如果要改成欧氏距离，索引也得改成 `vector_l2_ops`。

# 第 5 部分：冒烟接口（临时，M7-2 后删）

新建 `src/main/java/com/interviewmind/modules/interview/controller/VectorSmokeController.java`

```java
package com.interviewmind.modules.interview.controller;

import com.interviewmind.common.result.Result;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.ai.document.Document;
import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;

/**
 * 临时冒烟接口：验证"能存进去、能按语义搜出来"。
 * M7-2 接上真实知识库后就删掉。
 */
@Slf4j
@RestController
@RequestMapping("/api/dev/vector")
@RequiredArgsConstructor
public class VectorSmokeController {

    private final VectorStore vectorStore;
    private final EmbeddingModel embeddingModel;

    /** 响应结构：命中哪些文字、相似度多少 */
    public record VectorHit(String text, Double score, Map<String, Object> metadata) {
    }

    /** ① 灌 4 段测试文字 */
    @PostMapping("/seed")
    public Result<Integer> seed() {
        List<Document> documents = List.of(
                new Document(
                        "Redis 缓存穿透是指查询一个数据库里也不存在的 key，导致每次请求都打到数据库。常见方案是布隆过滤器或缓存空值。",
                        Map.of("topic", "redis", "type", "穿透")),
                new Document(
                        "Redis 缓存击穿是指某个热点 key 过期的瞬间，大量并发请求同时打到数据库。常见方案是互斥锁或逻辑过期。",
                        Map.of("topic", "redis", "type", "击穿")),
                new Document(
                        "MySQL InnoDB 使用 B+ 树作为索引结构，非叶子节点只存键，叶子节点存数据并用链表相连，适合范围查询。",
                        Map.of("topic", "mysql")),
                new Document(
                        "HashMap 扩容时容量按 2 倍增长，保证容量是 2 的幂，从而用 (n-1) & hash 替代取模运算。",
                        Map.of("topic", "java"))
        );

        vectorStore.add(documents);
        log.info("已写入 {} 条测试向量", documents.size());
        return Result.success(documents.size());
    }

    /** ② 按语义搜索 */
    @GetMapping("/search")
    public Result<List<VectorHit>> search(@RequestParam("q") String query,
                                          @RequestParam(value = "topK", defaultValue = "3") int topK) {
        SearchRequest request = SearchRequest.builder()
                .query(query)
                .topK(topK)
                .build();

        List<Document> documents = vectorStore.similaritySearch(request);

        List<VectorHit> hits = new ArrayList<>();
        if (documents != null) {
            for (Document document : documents) {
                hits.add(new VectorHit(document.getText(), document.getScore(), document.getMetadata()));
            }
        }
        return Result.success(hits);
    }

    /** ③ 看看模型到底输出多少维 */
    @GetMapping("/probe")
    public Result<Map<String, Object>> probe() {
        float[] vector = embeddingModel.embed("Redis 缓存击穿");
        return Result.success(Map.of(
                "dimensions", vector.length,
                "first5", List.of(vector[0], vector[1], vector[2], vector[3], vector[4])
        ));
    }
}
```

## 逐块解释

### ① `VectorStore` 是什么

Spring AI 提供的一个统一接口：

```java
public interface VectorStore {
    void add(List<Document> documents);                          // 存
    List<Document> similaritySearch(SearchRequest request);      // 按语义搜
    void delete(List<String> idList);                            // 删
}
```

**好处**：你的代码只认这个接口，不认 Postgres。将来换成 Milvus、Qdrant、Elasticsearch，业务代码一行不用改 —— 只换依赖和配置。

这和"用 `ChatClient` 不直接用 DeepSeek SDK"是同一个思路：**面向接口，不面向实现**。

### ② `Document` 是什么

Spring AI 的"文档单元"，三个部分：

```java
new Document(
    "正文内容",                                  // 会被向量化
    Map.of("topic", "redis", "type", "击穿")     // metadata：不会被向量化
)
```

**metadata 是干什么的**：存"这段文字从哪来"。将来检索出来，你可以告诉用户"参考了《Redis 实战》第 3 章"。

它还能用来**过滤**：

```java
.filterExpression("topic == 'redis'")   // 只在 redis 类文档里搜
```

这个在 M7-3 会很有用（评分 MySQL 题时，只检索 mysql 相关文档）。

### ③ `SearchRequest.builder()` 为什么用 builder

因为它有 4-5 个可选参数（topK、阈值、过滤条件），用构造器会变成 `new SearchRequest(query, 3, 0.5, filter, ...)` 这种全是位置的调用，改一个参数就得数位置。

**Builder 模式**让每个参数都有名字：

```java
SearchRequest.builder()
        .query(query)
        .topK(topK)
        .similarityThreshold(0.5)      // 只要相似度 ≥ 0.5 的
        .build();
```

### ④ `document.getScore()` 怎么读

在 `COSINE_DISTANCE` 模式下，Spring AI 返回的是**相似度**：

| 分数 | 含义 |
|---|---|
| 0.9 以上 | 几乎同义 |
| 0.6 – 0.9 | 相关 |
| 0.3 – 0.6 | 弱相关 |
| 0.3 以下 | 基本无关 |

⚠️ **它不是"距离"**。距离是本步说的"夹角"，越小越近；Spring AI 已经帮你转成了"相似度"，**越大越相似**。

### ⑤ `probe` 接口为什么值得写

因为它能**一眼验证三处是否一致**：

```
probe 返回 1024      ← 模型输出
表定义 vector(1024)  ← 数据库
配置 dimensions=1024 ← 应用
```

如果 probe 返回 1536，说明模型名配错了（用成了别的模型）。

## 6.4 关键验证：语义搜索

**关键点：查询用的词，和文档里的词不一样。**

```powershell
# 文档里没有"热点 key 过期"这几个字连在一起，但有"过期的瞬间"和"热点 key"
curl.exe -s "http://localhost:8080/api/dev/vector/search?q=热点key过期后大量请求打到数据库&topK=2"
```

**这一步成功，说明 RAG 的地基通了。** 因为它们是按**意思**匹配上的，不是按关键词。

再试一个明确无关的：

```powershell
curl.exe -s "http://localhost:8080/api/dev/vector/search?q=红烧肉怎么做&topK=2"
```

期望：分数都很低（0.2–0.4），而且**仍然会返回 2 条**（因为 topK=2，没设阈值）。

> **这一点很重要**：向量检索**永远会返回 topK 条**，哪怕全都不相关。
>
> 所以真实使用时必须设**相似度阈值**（`similarityThreshold(0.6)`），否则你会把垃圾内容塞进提示词，模型就会基于垃圾编答案。

# 第 7 部分：常见错误

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `Could not resolve placeholder 'EMBEDDING_API_KEY'` | 环境变量没设 | 设置后**重开终端**，或改 `run-dev.ps1` |
| `401 Unauthorized` | key 无效 / 没带上 | 检查 `spring.ai.openai.api-key` 是否真的读到了 |

| `type "vector" does not exist` | V7 没跑，或扩展没装 | 手动 `CREATE EXTENSION IF NOT EXISTS vector;` |
| `column "content" does not exist` | 表名/列名和 Spring AI 约定不一致 | 必须叫 `vector_store` + 那 4 个列名 |
| 启动报 pgvector 相关错误，但开发环境正常 | 测试也去装配了 | 加 `spring.autoconfigure.exclude=...` |
| 搜索结果分数都很低（0.3 左右） | 正常，说明语义不同 | 对比一下"相关"和"无关"的分数差距 |
| 搜索返回空列表 | 表里没数据，或 topK 传了 0 | 先 `seed`，注意参数名是 `topK` |

# 第 8 部分：做完之后，想三个问题

1. **`seed` 调两次，表里是 4 行还是 8 行？**
   去 psql 数一下。如果想一下"为什么" —— 因为 `Document` 没指定 id，每次都是新 uuid，所以会重复插入 4 行。

   **这意味着：导入文档时必须自己管好"这个文档导过没有"**，否则重复导入会污染向量库。这是 M7-2 要解决的第一件事。

2. **把 `topK` 改成 10 会怎样？**
   表里只有 4 行，它还是会返回 4 条。想一下"topK 大于总数时怎么办"。

3. **`metadata` 里放文件路径有用吗？**
   有用。将来用户看到"这句话来自《Java 并发编程实战》第 4 章"，信任感会完全不同。**RAG 的一个隐形价值是"可追溯"。**
