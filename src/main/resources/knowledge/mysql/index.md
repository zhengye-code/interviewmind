# InnoDB 索引原理

## 为什么用 B+ 树而不是 B 树

B+ 树的非叶子节点只存键，不存数据，所以一个页能放更多键，扇出更大，树的层数更少。

层数少意味着查一次记录需要读的页更少，磁盘 I/O 更少。B 树的非叶子节点要存数据，扇出小，树更高。

另外 B+ 树的叶子节点之间用双向链表连接，范围查询只要定位到左端点然后顺着链表扫，而 B 树需要中序遍历。

## 聚簇索引与二级索引

InnoDB 的主键索引是聚簇索引，叶子节点直接存整行数据。一张表只能有一个聚簇索引。

其他索引是二级索引，叶子节点存的是主键值而不是行数据。所以通过二级索引查不在索引里的列时，需要先拿到主键，再回主键索引取整行，这个动作叫回表。

减少回表的方式是覆盖索引：让查询需要的列全部包含在二级索引里，这样就不需要回表。

## 最左前缀原则

联合索引（a, b, c）在 B+ 树里先按 a 排，a 相同再按 b 排，b 相同再按 c 排。

所以查询条件必须从最左列开始连续匹配才能用上索引：a、a+b、a+b+c 都可以，单独的 b 或 b+c 不行。

范围查询会中断后续列的使用：如果 a 用等值条件、b 用范围条件，那么 c 就无法继续利用索引顺序。

## 索引失效的常见场景

对索引列做函数运算或隐式类型转换，会让索引失效，因为 B+ 树里存的是原始值，函数之后的结果没有索引可用。

前导模糊查询（LIKE '%关键字'）也无法使用索引，因为无法确定起点。LIKE '关键字%' 可以用。

联合索引上不满足最左前缀，或者中间某列使用了范围条件，都会导致后面的列无法使用索引。
