# 公司订单服务线程池规范

## 定参必须从输入算起

不允许拍脑袋给数字，必须先用 QPS 和单任务耗时算出目标并发。

目标并发 = QPS × 平均耗时（秒）。例如 2000 QPS、80ms，目标并发约为 160。

## 强制的参数组合

核心线程数不得低于目标并发的 1.5 倍，用来吸收突发流量和长尾任务。

必须使用有界队列，容量不得超过 200。队列过大会导致排队延迟不可控，且 maximumPoolSize 形同虚设。

最大线程数设为核心的 2 倍，并且必须在设计文档里说明：队列未满之前不会创建超过核心线程数的线程。

## 禁止使用的配置

禁止使用 CallerRunsPolicy 直接在 Tomcat 工作线程上执行任务，它会把 Web 线程池拖死，并且在重试场景下放大流量。

禁止多个业务共用同一个线程池，风控和发券必须隔离，避免一个业务把线程占满拖垮另一个。

禁止无界队列，历史上曾因 LinkedBlockingQueue 无界导致堆积 OOM。

## 上线后必须观测的指标

必须观测 activeCount、queueSize、rejectCount、任务排队时间 P99、下游依赖 RT，以及 GC 和 CPU 使用率。

任何一个指标连续五分钟超过阈值，就要触发扩容或降级。

## 回滚要求

线程池参数必须支持动态调整，且要保留一份旧参数配置，出问题能在五分钟内回退。

回滚方案要提前写进设计文档，不允许上线后再补。
