# HashMap 的实现要点

## 数据结构

JDK 8 之后 HashMap 是数组加链表加红黑树的组合。

数组的每个位置叫桶，哈希冲突时同一个桶里的元素用链表串起来。当链表长度达到 8 且数组长度达到 64 时，链表会转成红黑树，把最坏情况的查找从 O(n) 降到 O(log n)。

## 扩容机制

HashMap 的容量始终保持 2 的幂，默认是 16。扩容时容量翻倍。

保持 2 的幂是为了用位运算代替取模：当 n 是 2 的幂时，hash 与 n-1 做按位与，结果等价于 hash 对 n 取模，但位运算更快。

扩容后元素的位置只有两种可能：留在原下标，或者移动到原下标加旧容量的位置。判断依据是 hash 与旧容量那一位是 0 还是 1。

## 线程安全问题

HashMap 不是线程安全的，并发扩容可能造成数据丢失。

多线程场景应该使用 ConcurrentHashMap，它通过 CAS 配合桶级别的加锁来控制并发，读操作基本无锁。

JDK 7 的 HashMap 在并发扩容时可能形成环形链表导致死循环，JDK 8 改成尾插法后不再有死循环，但仍然会丢数据。

## hashCode 与 equals 的约定

往 HashMap 里放元素时，先比较 hash 值定位到桶，再用 equals 判断是否同一个键。

所以如果重写了 equals 而没重写 hashCode，两个「相等」的对象可能落到不同的桶里，导致 HashMap 里出现重复键。

反过来，只重写 hashCode 而不重写 equals，同一个桶里的元素仍无法正确判断相等，Map 的 get 会取不到值。
